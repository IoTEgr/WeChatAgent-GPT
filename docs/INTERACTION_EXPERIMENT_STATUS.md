# 引用与拍一拍实现状态

2026-10-27：纯后台原生服务已通过实际验收。引用气泡和拍一拍均有发送端本地记录，用户确认电脑微信正常显示；不需要自动操作微信窗口。

- 在微信自身协程任务队列内，按当前聊天及服务器消息 ID 查询完整 MessageData，再由微信自身构造、复制消息对象。不能在线程外直接调用需要协程环境的服务。
- 引用采用正常 TextMessageSendSource，类型 49、子类型 57、发送场景 7，引用 ID 和完整消息快照均由原生函数生成，进入正常发送流程。验收已确认本地类型 `(57 << 32) | 49`、关联服务器 ID、正服务器回执和引用气泡。
- 拍一拍进入完整原生业务服务，保留服务器成功后的本地消息处理。验收已确认本地系统提示及用户可见显示。
- 旧 CGI 引用入口和拼接部分快照的实验仍禁止；旧 CGI 拍一拍组件不再作为运行时发送路径。安装版语音组件独立保留。
- 正式模块、宿主、配置均有白名单与账号校验。原消息须属于当前聊天、真实入站、非本人且在一小时内。每个交互绑定稳定消息 ID，经持久化账本防止回执不明时重复提交。
- 探测及 dry 模式不发送。每个微信进程最多保留 4096 个操作对象，以支持迟到回调；达到上限拒绝后续操作。不得释放仍被原生异步任务引用的对象。
