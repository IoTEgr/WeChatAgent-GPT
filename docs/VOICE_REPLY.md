# 微信语音回复

大肥鱼通过本机 ChatGPT 登录连接 GPT-Live，默认 Maple。配置为 `wechat.voice: { enabled: true, backend: "gpt-live", liveVoice: "maple", replyMode: "conversation" }`。无需复制令牌或填写开发者 API Key。认证和续期由本机 Codex 官方登录组件管理。

## 回复决策与自主语音

DSH 先结合聊天记录整理话题、说话人、情绪与言外之意，再选择表情包、文字、颜文字、微信黄脸或语音。能够用一张表情表达时可单发表情，不附加解释。表情优先检索本地图库，其次已安装的微信合集；有可用素材时不查共享表情池，没有合适素材才查共享池。人格允许独立判断、接梗、幽默反驳不合理要求。

普通聊天默认文字，接梗可以单发表情包，声音确实有表现力或对方明确要求时再选语音，不设置固定比例。只有当前消息明确要求语音、初次决策却仍输出文字时，才进行一次形式复核。已经决定回应后，复核只选择发送媒介。复核返回 SILENT、OBSERVE、DEFER、格式错误或调用失败时保留原来的有效回复，不把它吞掉；生成期间真正收到安静指令、连接变化或权限变化时仍会取消未发送内容。

语音决策输出 `[语音回复:简短背景摘要]`，摘要不包含指定台词。宿主从当前账号、当前聊天的最近 300 条数据库记录中验证触发消息的 SHA256 标识，截取截至该条消息的最多 100 条记录，并附上当前人格和摘要。单条最多 1600 字符，包含摘要、画面事实和消息正文的启动历史按 24000 UTF-8 字节控制，长消息较多时保留最近记录。V3 启动接口限制为 128 个文本条目和 8192 个估算 token，因此条数与长度同时设限，不把整群历史无限追加。不会纳入触发消息之后的内容、其他聊天或其他账号记录。GPT-Live 接收有角色标注的会话历史，并被请求自主说出一条简短回复。既不要求逐字朗读，也不将 DSH 的摘要当成回复正文。真实语音转录随发送回执记录，供后续轮次理解已经说过什么。

当前 Codex GPT-Live V3 路径的启动历史和追加消息只支持文字，图片由 DSH 当前的视觉模型读取。含相关附图的语音决策必须追加 `<voice_images>{"I1":"可见主体、画面文字和关键细节"}</voice_images>`，只允许本轮真实相关的图片编号；未能读取填 null，不能猜测。观察结果作为结构化数据通过持久化 outbox 和 OneBot 传入语音宿主，不作为聊天正文发送。宿主再核对图片所属聊天及来源消息位于触发消息之前，将观察事实单独交给 GPT-Live，让其自主评价、接梗和组织语音，不指定答案台词。形式复核或格式修复会保留同一批图片，避免图片卸载后丢失依据。历史图片未重新附图时只保留占位，不声称读到了画面。

`replyMode: "conversation"` 也会将旧插件输出的 `[语音TTS:台词]` 转为基于当前聊天的自主语音，丢弃台词。兼容的 `replyMode: "read"` 保留原来的朗读功能。新的上下文语音必须独立成条，不能同时混入正文；可与拍一拍控制一同使用。语音与表情包同轮互斥。

启用语音只代表语音可用；“问候与生活关心”默认简短文字，声音确有表达价值且方便收听时才选择自主语音。主动语音携带 `purpose: "proactive"`，明确没有新的好友消息，`replyTo` 为 null，可使用结束于自己发言的历史，也允许尚无历史；旧消息不套用普通即时回复的一小时触发限制。发起端必须提供当前主动机会的上下文指纹，发送服务在生成前和提交前均核对主动设置、允许时段、空闲状态、聊天快照和当前账号。GPT-Live 按人格、兴趣、真实历史和话题概要自主开场，不朗读拟好的台词，也不把旧记录当成待回答问题。实际转录进入历史以便避重；送达不明不改发。已确认未提交的生成失败才持久化改为一次非语音决策，重启后也不会重新尝试该轮语音。

## 音频与送达

通过 Codex app-server 的实验性 `thread/realtime/*` WebRTC 通道连接 `gpt-live-1-codex`。每条语音创建独立临时会话，不接入麦克风、不执行工具。初始历史仅包含相关聊天与人格，连接就绪后通过宿主开发者消息请求一次自主回应。

接收 Opus 音频，重采样为 24 kHz、单声道、16-bit PCM，收到完整转录、轮次结束及尾音后关闭会话并编码为微信 SILK。协商 NACK 重传，并启用 128 包乱序缓冲；按采样时间戳保留停顿、移除重叠采样，结束后再留 3 秒接收尾音。自主语音检查转录完整、非空及长度，不要求与摘要一致。朗读模式额外核对台词。丢包过多、超时、登录或额度失败时不发送残缺语音，也不切换其他合成引擎。

匹配微信为 4.1.10.27；发送服务使用本机 token。仅在数据库出现新的 outgoing/localType=34 与有效 serverId 时确认送达。持久化请求只提交一次；回执不明不自动重发。新语音生成失败时不会把上下文摘要或预写台词改成文字发送；明确确认未提交微信时，把本批输入保留为未处理，原子撤下失败语音并记录仅本轮有效的语音不可用状态，再交给模型按真实上下文选择表情包、文字、微信黄脸或颜文字等替代表达；不向群友发送技术故障模板，不把上下文摘要当成正文。本轮禁止再次选择语音，替代回复完成后恢复下一轮正常语音偏好。已提交或回执不明的语音不触发改发。静音检测等待 20 秒，再关闭该会话，预算足够时最多重新连接一次。状态文件只记录阶段、耗时、收包和丢包数、转录长度及音频时间戳统计，不记录聊天正文、账号或令牌。

`scripts/tts/say.mjs --request-file context.json` 仅在本地生成音频，不发送微信消息。上下文 JSON 由 `scripts/voice-context.mjs` 生成；兼容的 `--text "短句"` 仅用于明确朗读。生成预算及外层编码和回执预算统一定义在 `voice-protocol.js`。

参考：[官方会话管理](https://developers.openai.com/api/docs/guides/live-conversations)、本机 `app-server generate-json-schema --experimental` 的对应版本协议。实验接口可能随官方组件更新变化。
